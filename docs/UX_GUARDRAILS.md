# UX Guardrails (Non-negotiable)

These guardrails protect the core promise: **"Trust the plan. Stop worrying."**

---

## 1. The Plan Is Pre-Made

- User opens app → sees today's plan already built
- NO requirement to allocate, prioritize, or decide before seeing the plan
- The first screen answers: "What does 'enough' look like today?"
- User's only decision: "Ready to start?" or "Not today"

**Why**: If the user has to plan before working, we've failed. The app plans. The user executes.

---

## 2. "Enough" Is Explicit and Celebrated

- Daily "enough" threshold must be visible
- When "enough" is reached, actively tell the user to STOP
- Transition to "life mode" should feel like an achievement, not abandonment
- Never imply "you could do more" after enough is hit

**Why**: The promise is that "enough" means enough. If we undermine this, trust breaks.

---

## 3. Bad Days Are First-Class Citizens

- "Rest Day" or "Not Today" is always one tap away
- NO guilt language: no "you'll fall behind," no "are you sure?"
- Redistribution happens automatically and is communicated clearly
- If deadlines are still safe after a bad day, say so explicitly

**Why**: Users must trust that the system can absorb bad days. Fear of bad days = anxiety = failure.

---

## 4. Touch Is Low-Stakes

- Touch is acknowledgement, not commitment
- Always provide Undo (generous window, not 5 seconds)
- Mis-taps must never cause real problems
- No "you said you'd do this" guilt from logged touches

**Why**: If logging work feels risky, users won't log. Logging must be casual and reversible.

---

## 5. No Shame Mechanics

Do NOT add:
- Overdue / missed / failure states with red warnings
- Streaks or streak-breaking penalties
- Completion percentages that make 80% feel like failure
- "You should have..." retrospective guilt
- Comparisons to past performance or other users

**Why**: Shame doesn't motivate people with executive dysfunction. It paralyzes them.

---

## 6. Focus Mode Is Optional and Safe

- Always optional — never required to log work
- Can exit anytime with no penalty
- "Leave early" = "Finish" — both are valid exits
- No strict countdown creating time pressure
- No "you only did 23 minutes" judgment

**Why**: Focus Mode is a container for concentration, not a cage. Users must feel safe to leave.

---

## 7. The Math Is Verifiable (When Wanted)

- User should be able to see WHY something is scheduled
- Deadline calculations should be inspectable
- "You're on track" should be backed by visible reasoning
- But: math should be hidden by default, available on demand

**Why**: Trust requires verifiability. But showing math constantly creates anxiety. Balance: available, not prominent.

---

## 8. Habits Are Real Commitments (Planned Feature)

- Habits (gym, reading, etc.) scheduled like work sessions
- Not "optional extras" — they're part of the plan
- Missing a habit triggers redistribution, not guilt
- Habits protect life-outside-work time

**Why**: If habits are skippable extras, they'll always lose to work. They must be equals.

---

## 9. Tone and Copy

**Use:**
- "Here's today's plan"
- "You've done enough"
- "Take the rest of the day"
- "I've adjusted the schedule"
- "Still on track"

**Avoid:**
- "You should..." / "You need to..."
- "Don't forget to..."
- "You missed..." / "You're behind..."
- "Optimize" / "Maximize" / "Be more productive"
- "Accountability" / "Discipline" / "Commitment"

**Why**: Language shapes experience. Permission-based, not pressure-based.

---

## 10. The System Carries the Load

The user should never feel they need to:
- Remember what to do next (the app shows it)
- Calculate if they're on track (the app calculates)
- Decide when to stop (the app decides)
- Feel guilty about rest (the app permits it)
- Worry about deadlines (the app worries for them)

**Why**: This is the entire value proposition. If users still carry mental load, we've built a todo list, not a worry-offloading system.

---

## Summary

Every UX decision should pass this test:

> "Does this reduce the user's mental load, or add to it?"

If it adds load — even slightly — find another way.
